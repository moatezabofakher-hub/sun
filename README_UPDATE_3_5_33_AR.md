# تحديث التطبيق الرئيسي 3.5.33 — فواتير مناقلة قابلة للتعديل

## ما الذي تغيّر؟

- كل عملية في سجل المناقلات تظهر الآن **كفاتورة مناقلة** مستقلة فيها رقم مرجعي ثابت، وتاريخ، واسم المستودع المُرسل والمستلم، وجدول جميع الأصناف والكميات والوحدات والملاحظة.
- بعد فتح الفاتورة في السجل، اضغط **تعديل الفاتورة**: تُحمّل كامل بياناتها في نموذج المناقلة القائم، مع استمرار عرض المواد في الشبكة وإمكانية تعديل الكميات ووحدات القياس، وإضافة/إزالة الأصناف، وتغيير المستودعات والتاريخ والملاحظة.
- عند الحفظ يُستبدل محتوى الفاتورة الأصلية دون إنشاء عملية جديدة أو تغيير رقمها؛ تبقى جميع الأصناف داخل فاتورة واحدة مع الحفاظ على هوية السطور الباقية وتاريخ الإنشاء.
- لن يظهر زر «حفظ ملف المناقلة» في السجل؛ لا حاجة لتصدير ملف JSON من أجل مراجعة المناقلة أو تعديلها. بقيت وظيفة التصدير البرمجية القديمة لأغراض التوافق، دون زر في الواجهة.
- زر «إلغاء الفاتورة» لا يزال متاحًا لعكس جميع مواد المناقلة إذا سمح رصيد المستودع المستلم بذلك.
- التحقق من الرصيد يتم وفق الأثر الصافي للتعديل: تُعكس المناقلة القديمة حسابيًا، ثم تُطبّق الجديدة على أرصدة افتراضية قبل الحفظ. يمنع النظام حفظ فاتورة إذا تسبب التعديل في رصيد سالب لأي صنف في أي مستودع متأثر، بما في ذلك عندما تكون البضاعة المستلمة قد بيعت لاحقاً.
- إذا فشل حفظ التعديل، تُستعاد جميع بيانات وأرصدة المناقلة الأصلية ولا تُضاف عمليات مكررة.
- عمليات المناقلة المخزنة في الإصدارات السابقة — سواء ذات معرف `batchId` أو السجلات القديمة المنفردة — يمكن فتحها وتعديلها بالطريقة الجديدة.
- يعدّل الإصدار **التطبيق الرئيسي فقط**، مع المحافظة على المزامنة التلقائية المستمرة التي أُضيفت في 3.5.32 دون تغيير تطبيق المندوب.

## تثبيت التحديث

- إصدار الرئيسي: `versionCode 40`، `versionName 3.5.33-editable-transfer-invoices`.
- إصدار المندوب يبقى `1.2.3-auto-continuous-sync` (`versionCode 6`).
- إن كان مشروع GitHub الحالي هو 3.5.32، فكّ ضغط `UPDATE_MAIN_3_5_33_EDITABLE_TRANSFER_INVOICES_CHANGED_FILES.zip` وارفع الملفات داخل مساراتها دون حذف بقية الملفات، أو استخدم المشروع الكامل.
- شغّل workflow بناء التطبيق الرئيسي المعتاد؛ حزمة ZIP هي **ملفات مصدر Android وليست APK جاهزًا**.
- خذ نسخة احتياطية قبل التثبيت، ولا تحذف التطبيق المثبت، ويجب توقيع التحديث بالمفتاح نفسه لاستبقاء قاعدة البيانات.

## اختبارات التحديث

- `tests/test_editable_transfer_invoices_3533.js` يغطي فتح الفاتورة وتحرير البيانات الأصلية وتثبيت الرقم والهوية، تعديل المستودعات، منع الأرصدة السالبة، استرداد الحالة بعد فشل الحفظ، إزالة صنف، وتوافق البيانات القديمة.
- `tests/test_transfer_bulk_grid_3526.js` يراجع شبكة اختيار الأصناف، الكميات والوحدات، حفظ العملية كمجموعة واحدة، وحماية رصيد المصدر.
- لم يُختبر بناء APK أو استخدام هاتف أندرويد حقيقي داخل البيئة.
