# دليل التوقيع الدائم — لا تحذف التطبيق القديم قبل نسخ بياناته

لتثبيت تحديث APK فوق الإصدار الحالي مع الحفاظ على بياناته **يشترط تطابق توقيع الحزمة**. إصلاح رقم الإصدار أو قاعدة البيانات وحده لا يكفي.

## استخدام مفتاح توقيع دائم

1. احتفظ بملف التوقيع الخاص الذي تحصل عليه منفصلًا في مكان آمن، **ولا ترفعه إلى GitHub أبدًا**.
2. افتح الملف `GITHUB_SECRETS_AR.txt` داخل الحزمة الخاصة؛ به أربع قيم يجب إدخالها في GitHub Settings > Secrets and variables > Actions كأسرار مستقلة بحسب الأسماء.
3. ارفع **ملفات مشروع المصدر فقط** من ZIP التحديث إلى مستودعك مع المحافظة على المسارات الأصلية `.github/workflows`, `app` و`tests`.
4. شغّل workflow وانتظر البناء، وتحقق من أن الملف الناتج اسمه `ALMOHASEB-ALTEQNI-SIGNED-UPDATE.apk` لا `TEST-DEBUG-NOT-FOR-UPDATING.apk`.
5. استخدم المفتاح نفسه لكل إصدار؛ إذا فقدته لن تتمكن من تحديث التطبيقات الموقعة به مباشرة.

## شرط ضروري قبل التثبيت فوق تطبيق موجود

تطابق ملف `technical_accountant_release.jks` **الجديد** مع توقيع النسخة الحالية ليس مضمونًا؛ بل إذا كانت النسخة القديمة موقعة بمفتاح آخر فلا يمكن تثبيت الجديدة فوقها. صدّر النسخة الاحتياطية JSON **من التطبيق الحالي قبل أي حذف** وتحقق منها. إن توفر مفتاح النسخة القديمة الأصلي، يمكن بدلاً من المفتاح الجديد إدخاله كأسرار GitHub لكي تنجح الترقية مباشرة.

**لا ترفع** حزمة المفتاح الخاصة أو النسخ الاحتياطية أو ملفات تفعيل المالك إلى المستودع العام أو تشاركها مع الآخرين.
