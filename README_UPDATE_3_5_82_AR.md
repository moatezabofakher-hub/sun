# التقني للمحاسبة 3.5.82 — الرئيسي والكمبيوتر

## التغييرات
- وضع سطر «إصدار التطبيق» في أعلى صفحة الضبط *قبل* قسم «مزامنة الموبايل والكمبيوتر». في ويندوز يُقرأ الإصدار من `package.json` بدلاً من رقم قديم ثابت.
- أيقونة مدمجة للجهازين (كمبيوتر ↔ هاتف) لا تحتاج إلى اتصال بالإنترنت أو مكتبة أيقونات خارجية.
- إصلاح مزامنة موظفي البيع: دمج تعريفات الموظفين والهويات والمستودعات والمفاتيح المرتبطة بهم، إضافة إلى سجلات استلام عمليات المندوبين ودفعاتهم. أي اختلاف في تعديل الموظف نفسه أو في هوية ربط موظفين نشطين يوقف الدمج ويظهر في سجل التعارض.
- وسم جهاز إنشاء السجل الجديد: الكمبيوتر أو الموبايل الرئيسي. لا يتغير الوسم عند مزامنة السجل، ولا يُنسب تلقائياً أي سجل تاريخي لا يحمل وسماً إلى جهاز بعينه.
- عرض الوسم داخل قوائم الفواتير والسندات والمصاريف والمناقلات وتعريفات الموظفين.

## الاحتياطات
- عند وجود موظفين مقترنين بشكل مستقل على الكمبيوتر والهاتف مع معرفَي شركة مختلفين، سيظهر تعارض يتطلب المراجعة. لا تختَر هوية من الجهازين دون التحقق من اقتران أجهزة المندوبين؛ اعتماد إحدى الهويتين قد يتطلب إعادة ربط بعض الأجهزة.
- قبل أول مزامنة بعد التحديث، أنشئ نسخة احتياطية خارجية على الجهازين. لا تتم المزامنة دون ربط مسبق وموافقة أولية عند الطلب.
- لا تُحذف حسابات العملاء أو الفواتير أو سجلات المندوبين القديمة ولا يُعاد ترقيمها إلا وفق آلية التعارض السابقة.
- رقم الإصدار: ويندوز 3.5.82، أندرويد الرئيسي 3.5.82 برمز إصدار 86. يجب البناء بمفتاح توقيع أندرويد نفسه المستخدم سابقاً لكي يقبل النظام التحديث فوق التطبيق المثبت.

## البناء
- Android: فك محتويات ملف ZIP إلى جذر مستودع أندرويد، ثم تشغيل GitHub Actions للبناء الموقّع (يتطلب إعداد أسرار التوقيع).
- Windows: فك محتويات ملف ZIP إلى جذر مستودع ويندوز ثم تشغيل GitHub Actions الخاص ببناء EXE.
- لم يُجرَ اختبار فعلي لنقل البيانات بين كمبيوتر وهاتف حقيقيين في هذه الجلسة، وإنما اختبار الدمج وحفظ البيانات ضمن اختبارات Node ومراجعة المصدر.
