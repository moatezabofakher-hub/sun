# إصلاح كاميرا الباركود — المحاسب التقني

تم التأكد من أن آخر مستودع منشور على GitHub كان بلا إذن CAMERA وبلا جسر NativeBarcode.
هذه الحزمة تحتوي فقط على الملفات التي يجب استبدالها، ولا تُغيّر ملف قاعدة البيانات أو التراخيص.

## طريقة الرفع من GitHub Desktop (مرة واحدة)
1. تأكد من اختيار مستودع sun، وليس mizo، واضغط Fetch origin ثم Pull origin إن ظهر.
2. اضغط Show in Explorer لفتح مجلد المستودع المحلي.
3. فك ضغط هذه الحزمة، ثم انسخ محتوياتها (مجلدي app و tests، والملف الإرشادي) إلى داخل مجلد sun. اختر Replace/استبدال عند السؤال، مع الاحتفاظ بهيكل المجلدات.
4. في GitHub Desktop ستظهر الملفات المعدلة. اكتب Camera barcode fix واضغط Commit to main ثم Push origin.
5. افتح GitHub Actions وانتظر نجاح Build SAN SHINE Android APK، ثم حمّل الـ ZIP من Artifacts وفك ضغطه لتجد app-debug.apk.

## كيف تختبر الكاميرا
- افتح التطبيق الجديد، ثم المواد > إضافة مادة > تصوير باركود.
- اسمح للكاميرا أثناء الاستخدام عندما يطلب النظام إذنها.
- إن عملت الكاميرا، جرّب باركود حقيقياً ذا إضاءة واضحة. في الفاتورة يجب أن تكون المادة محفوظة مع رقم باركودها حتى يُعثر عليها.

## تنبيه حفظ البيانات
الحزم المسماة «اختبار منفصل» تستخدم معرّف تطبيق مختلف، وتثبت بجانب التطبيق القديم ولا تنقل حساباته تلقائياً.
أما حزمة «تحديث التطبيق نفسه» فتحافظ على معرف التطبيق، لكن GitHub Actions ينشئ APK تجريبياً بتوقيع قد يختلف عن النسخة المثبتة؛ قد يرفض الهاتف التثبيت فوق التطبيق.
لا تحذف التطبيق المثبت قبل تصدير نسخة احتياطية من التطبيق، والتحقق من أنها محفوظة خارج مجلد التطبيق.

## حدود التحقق
اجتازت الملفات الاختبارات المحلية للنصوص والـ JavaScript والمنطق المحاسبي والتراخيص؛ لم يُبن APK فعلي لهذا الإصلاح ضمن بيئة العمل ولم يُختبر على هاتف حقيقي.

**هذه حزمة اختبار منفصل، ولا تستبدل التطبيق المثبت.**
