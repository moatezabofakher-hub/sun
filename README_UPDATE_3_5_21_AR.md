# المحاسب التقني — تحديث الإصدار 3.5.21

## رقم الإصدار
- Android versionCode: 28
- Android versionName: `3.5.21-invoices-reports-profiles`
- معرّف التطبيق ثابت: `com.sunshine.technicalaccountant`.
- توقيع الإنتاج: تستخدم عملية GitHub Actions `Technical Accountant - Signed APK` الأسرار الأربعة الموجودة مسبقاً؛ لا تعِد إنشاء مفتاح توقيع مختلف.

## 1. المبيع والشراء والمردود
- واجهة إضافة المواد أكثر وضوحاً مع بطاقات وأزرار بتدرّج بصري خفيف وفواصل بين أسطر المواد.
- يحتفظ كل بند برقمه في الفاتورة وفي النسخة المطبوعة؛ تمت إضافة فاصل منقط بين البنود على ورق الطابعة الحرارية وعدد بنود الفاتورة.
- لم تُغيّر خوارزميات ترحيل الفواتير أو إنشاء القيود المالية.

## 2. طباعة إجمالي المواد المباعة
- افتح «التقارير» ثم «ملخص حركة المواد المباعة».
- يدعم اليوم، الأمس، الكل، تاريخاً محدداً، أو فترة من/إلى.
- يتم استخراج الكمية والقيمة من فواتير المبيعات وخصم مردود المبيعات؛ الحسم والضريبة موزّعان على البنود مع ضبط فرق التقريب في البند الأخير لتطابق القيمة صافي الفواتير.
- يحافظ التقرير على فصل الأصناف حسب الوحدة وعملة الفاتورة؛ لا يُجمع الدولار والليرة في إجمالي واحد.
- سجلات الفواتير القديمة التي لا تضم تفاصيل المواد تظهر تحت بند «قيمة فواتير دون تفاصيل أصناف» للمحافظة على تطابق الإجمالي.
- اختر «طباعة حرارية» لإرسال التقرير إلى الطابعة المضبوطة عبر البلوتوث.

## 3. طباعة إجمالي الديون
- من التقارير اختر «تقرير الذمم المالية»، ثم «لنا» أو «علينا» و«طباعة حرارية».
- تقرير كل جانب مستقل بأسماء الحسابات وقيم USD/SYP والأرصدة الافتتاحية والتغيرات من الفواتير والسندات.

## 4. الحسابات المستقلة للشركات
- افتح الضبط ← «الحسابات المستقلة للشركات».
- أنشئ حساباً جديداً باسم الشركة، ثم تستطيع التبديل من المكان نفسه. كل حساب له مواد وفواتير وسندات وعملاء ومستودعات وإعدادات مستقلة.
- يحفظ التطبيق نقطة استرجاع محلية قبل التبديل، ويحتفظ بصورة الشركة السابقة في IndexedDB.
- تشتمل ملفات النسخ الاحتياطي المصدَّرة على اسم الشركة ومعرّف حسابها، وتُعرَض رسالة تحذير إذا حاولت استيراد نسخة تخص حساباً آخر.
- يتطلب الاسترجاع من حساب مختلف التحقق من كلمة سر الحساب الذي صدر منه الملف. وإذا كان الحساب الحالي محمياً فيجب إدخال كلمته أيضاً قبل الاستبدال. النسخ التي لا تحتوي كلمة سر للمصدر لا تسمح بالاستعادة عبر الحسابات.
- **مهم:** حفظ النسخ بصيغة JSON غير مشفّرة؛ كلمة السر هي حاجز واجهة وليس بديلاً عن تشفير الملف أو التوقيع الرقمي. احتفظ بملفات النسخ بعيداً عن الآخرين. لا ترفعها إلى GitHub العام.
- الحفظ التلقائي المحلي / Drive يحتفظ بلقطة الحساب النشط وقت التنفيذ؛ صدّر نسخة يدوية مستقلة لكل شركة لتغطية جميع الشركات.
- نقاط الاسترجاع الموجودة داخل IndexedDB تضيع عند مسح بيانات التطبيق أو حذفه. صدّر نسخة خارجية لكل شركة واختبر الاستعادة قبل أي حذف أو ترقية كبرى.
- ترخيص الجهاز وعدد العمليات التجريبية يظلان مشتركَين بين الشركات حتى لا يعاد ضبط حد التجربة بإنشاء حساب جديد.

## 5. التثبيت الآمن من GitHub
1. خذ نسخة احتياطية صالحة من الحساب الحالي **ومن كل شركة إضافية** على حدة، قبل استبدال التطبيق.
2. حمّل حزمة الملفات المعدلة وفك ضغطها على هاتفك. ارفع الملفات إلى **المسارات نفسها** داخل المستودع (ولا ترفع ZIP فقط).
3. تحقق من رفع `app/build.gradle` بالإصدار 28 وتحديث HTML وJava والاختبارات.
4. افتح Actions ← `Technical Accountant - Signed APK` ثم شغّل العملية من الفرع `main`.
5. بعد النجاح حمّل الأثر `ALMOHASEB-ALTEQNI-SIGNED-UPDATE` وفك ضغط APK الناتج.
6. ثبّته فوق الإصدار السابق فقط إذا كان التطبيق الحالي موقّعاً بالمفتاح الدائم نفسه؛ لا تحذف التطبيق القديم لمجرد ظهور تعارض التوقيع، بل تأكد من النسخ الاحتياطية أولاً.

## الاختبارات والحدود
- فحص بنية الملفات وJavaScript واختبارات المحاسبة والمخزون والحماية والديون والواجهة والترخيص وإدارة النسخ الاحتياطية اجتاز الفحص المحلي.
- اختبار واجهة متصفح بمحاكاة لمخزن IndexedDB وبلوتوث الطابعة، وليس ضماناً لسلوك Android أو عتاد Xprinter الحقيقي.
- يلزم التحقق ميدانياً من استعادة نسخ شركات مختلفة ومن قص/وضوح طباعة 80 مم قبل الاستخدام المالي الفعلي.
