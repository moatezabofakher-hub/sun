# المحاسب التقني | إصدار 3.5 — المستودعات والمصاريف

## ما الجديد
- مستودعات متعددة (تعريف مستودع، تغيير اسمه، اختيار المستودع الافتراضي).
- مناقلة المواد بين المستودعات مع اختيار الوحدة (الكرتونة/القطعة وغيرها بحسب تعريف الصنف).
- التحقق من كمية المخزون بالمستودع المصدر؛ تمنع المناقلة التي تتجاوز الرصيد.
- سجل مناقلات مع إمكانية عكس العملية فقط حين يتوفر الرصيد اللازم في المستودع المستلم.
- اختيار المستودع في فواتير المبيعات والمشتريات والمرتجعات، ومنع بيع كمية تتجاوز رصيد المستودع المختار.
- عرض رصيد كل مستودع وجرد إجمالي المستودعات.
- حساب مصاريف نقدية بتاريخ وفئة وعملة (ل.س/دولار) وسعر صرف مع إمكانية تعديل المصروف وحذفه.
- مصاريف نقدية تُنقص الصندوق وتظهر بفئة وكمية ضمن تقرير الأرباح للفترة المختارة.
- حساب صافي الربح التقديري = الربح التقديري للمبيعات - المصاريف خلال الفترة.
- الحفاظ على دعم الكاميرا ومسح الباركود المتعدد والطباعة والبصمة والنسخ الاحتياطية والتراخيص الحالية.

## تفسير المخزون القديم
كل البضاعة الافتتاحية المسجلة سابقاً والفواتير التي ليس فيها مستودع محدد تُنسب آلياً إلى "المستودع الرئيسي".
لا يغيّر التحديث معرف قاعدة IndexedDB أو أسماء حقول الفواتير الأساسية.
المناقلة لا تُعد بيعاً أو شراءً، ولا تؤثر على مجموع المخزون لجميع المستودعات.

## مهم جداً بخصوص بياناتك وتوقيع APK
هذه ملفات مصدر لإنشاء APK عن طريق GitHub Actions وليست APK مبنياً ومختبراً على هاتفك.
مُعرّف التطبيق في نسخة التحديث هو **com.sunshine.technicalaccountant** كما كان في إصدار 3.4،
واسم قاعدة البيانات **AlRaedAccountingERP_v2** وإصدار بنيتها **1**؛ لم يتم تغييرهما.
رغم ذلك، تثبيت التحديث فوق التطبيق القديم يتطلب أن يكون توقيع APK مطابقاً لتوقيع التطبيق المثبّت.
ملفات GitHub Actions من نوع Debug قد تُوقّع بمفتاح مختلف بين عمليات البناء، لذلك من الممكن رفض التحديث.

**قبل أي محاولة:**
1. افتح التطبيق المثبت حالياً → الإعدادات → النسخ الاحتياطي → تصدير JSON.
2. احفظ ملف النسخة الاحتياطية في مكان مستقل (أو Google Drive) وتأكد أنه يحتوي على ملفات المواد والفواتير والعملاء.
3. لا تحذف التطبيق القديم ولا تمسح بياناته قبل التأكد من النسخة الجديدة.
4. إذا رفض أندرويد تحديث النسخة بسبب اختلاف التوقيع، لا تحذف النسخة القديمة! استخدم نسخة الاختبار المنفصلة (Safe Test) واستورد JSON.
5. من الأفضل إعداد مفتاح توقيع ثابت لإصدارات APK المستقبلية، ولا ترفع أي مفتاح خاص إلى GitHub العام.

## استخدام المستودعات
من الشاشة الرئيسية اضغط "المستودعات والمناقلات"، ثم:
1. أضف مستودعات بأسماء مختلفة.
2. حدّد المصدر والوجهة والمادة والوحدة والكمية، ثم احفظ المناقلة.
3. اختر المستودع عند إنشاء فاتورة جديدة؛ الفواتير القديمة تبقى في الرئيسي.
4. من التقارير → جرد المستودع، اختر مستودعاً معيناً أو إجمالي جميع المستودعات.

**ملاحظة:** لا يمكن حذف مستودع له حركات أو أرصدة. يمكن إعادة تسميته.

## استخدام المصاريف
من الشاشة الرئيسية اضغط "المصاريف"، ثم أدخل المبلغ والعملة والفئة والتاريخ وسعر صرف العملية.
المصروف هنا هو **مصروف نقدي مدفوع من الصندوق**، وليس مصروفاً مستحقاً على الذمة.
إذا سجلت مصروفاً هنا، **لا تسجل سند دفع منفصلاً للمصروف ذاته** وإلا ستخصم المبلغ من الصندوق مرتين.
عند تعديل مصروف أو حذفه يعاد احتساب أثره على الصندوق والأرباح تلقائياً.

اذهب إلى التقارير → الأرباح والمبيعات لاختيار الفترة، وستجد:
- إجمالي الربح التقديري قبل المصاريف (يظهر عند الضغط على إظهار الأرباح).
- إجمالي مصاريف الفترة بالدولار وما يعادلها بالليرة.
- صافي الربح التقديري بعد المصاريف (مخفي حتى الضغط على إظهار الأرباح).
- تفاصيل المصاريف حسب الفئات.

القيم المحوّلة للمصاريف تعتمد سعر صرف العملية لحساب المكافئ بالدولار، والمكافئ المعروض بالليرة يعتمد سعر الصرف الحالي.
أرباح المواد والفواتير تظل **تقديرية** بناءً على تكلفة الأصناف المسجلة، ولا تمثل محاسبة تكلفة مخزون متحركة دقيقة أو قيود دفتر الأستاذ العام الكاملة.

## رفع النسخة إلى GitHub Desktop
افتح مستودع `sun` على GitHub Desktop واضغط Show in Explorer، ثم فك ضغط ملف ZIP وانسخ **كل محتوياته** إلى جذر المستودع:
- `.github/workflows/`
- `app/`
- `tests/`
- `build.gradle`
- `settings.gradle`
- `gradle.properties`
مع الاستبدال عند الحاجة. ثم Commit to main وPush origin.
افتح Actions في GitHub وحمّل ملف APK من Artifacts بعد نجاح البناء.

## الأمان
لا توجد مفاتيح RSA الخاصة بتوليد التراخيص داخل الحزمة؛ تحقق التطبيق من التراخيص يعتمد المفتاح العام فقط.
اختبارات المصدر لا تضمن نجاح إصدار APK أو اختبار الميزات على الهاتف والطابعة فعلياً.
