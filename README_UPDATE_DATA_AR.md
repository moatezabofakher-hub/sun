# المحاسب التقني 3.4 — مسح متتابع وحماية البيانات القديمة

## ما الجديد؟

- أثناء فواتير البيع والشراء (وكذلك المردودات)، افتح أيقونة الكاميرا وامسح باركوداً بعد آخر. تبقى الكاميرا مفتوحة إلى أن تضغط زر **×** الواضح أعلى الماسح. تظهر عدادات القراءات أثناء المسح؛ عند الإغلاق تُضاف جميع المواد إلى الفاتورة التي كنت تعمل عليها.
- إذا مُسح باركود المادة نفسها أكثر من مرة، تزيد الكمية؛ لتجنّب التكرار العرضي، يتجاهل الماسح القراءة المتكررة نفسها خلال نحو 3.5 ثوانٍ. يمكن مسح باركود مختلف مباشرة بعد نحو نصف ثانية.
- تعرض الفواتير الآن **منطقة الأصناف المضافة** بلون أزرق سماوي واضح مع حدود زرقاء، في المبيعات والمشتريات.
- تبقى الكاميرا الخاصة ببطاقة إضافة مادة جديدة في وضع قراءة **باركود واحد**، لأن الحقل مخصص لمادة واحدة.
- ميزات الطباعة المباشرة والدعم عبر واتساب والبصمة وإدارة الحسابات محفوظة.

## حماية بياناتك قبل تحديث APK

1. في **التطبيق القديم المثبّت** افتح **الإعدادات ← النسخ الاحتياطي ← تصدير نسخة احتياطية**، واحفظ ملف JSON خارج مجلد التطبيق (مثل Downloads). كرّر الحفظ على Google Drive أو وسيط آمن آخر إذا أمكن.
2. تأكد أن ملف JSON موجود ويمكن فتحه، ويحتوي على أقسام مثل `accounts`, `items`, `invoices`, `vouchers`. **لا ترفع هذا الملف إلى مستودع GitHub العام** لأنه يحوي بيانات مالية وشخصية.
3. **لا تحذف التطبيق القديم ولا تمسح بياناته**. اختبر إصدار «نسخة اختبار مستقلة» إذا احتجت إلى التأكد من الماسح؛ هذه النسخة لها معرّف مستقل ولا تحتوي على بيانات التطبيق القديم تلقائياً.
4. النسخة المسماة «تحديث التطبيق الحالي» تحتفظ بنفس `applicationId = com.sunshine.technicalaccountant` وبنفس قاعدة البيانات `AlRaedAccountingERP_v2` وبنفس عنوان التخزين المحلي الآمن، وترفع `versionCode` فقط. لذلك، **إذا قبل أندرويد تثبيت APK كتحديث فوق التطبيق القديم دون إلغاء تثبيته**، يحتفظ عادةً ببياناته المحلية.
5. **لكن نجاح تحديث APK يتطلب أن يكون موقّعاً بنفس مفتاح التوقيع للنسخة القديمة.** ملفات APK من GitHub Actions من نوع debug غالباً ما تُوقّع بمفاتيح مختلفة بين عمليات البناء. إذا رأيت «لم يتم تثبيت التطبيق» أو «يتعارض مع حزمة موجودة»، **لا تزل النسخة القديمة لإجبار التثبيت**. احتفظ بها واستخدم النسخة المستقلة مؤقتاً، ويمكنك استيراد ملف JSON إليها لاستعادة البيانات عند الحاجة. قد تحتاج إلى إعادة تفعيل الترخيص في حزمة جديدة.
6. للمستقبل، اعتمد مفتاح توقيع إنتاج واحداً محفوظاً خارج المستودع العام، واضبط GitHub Actions على توقيع الإصدارات به؛ بدون المفتاح الذي وقّع النسخة الحالية لا يمكن ضمان ترقيتها مباشرة.

> **لا يوجد تحديث يستطيع ضمان سلامة بيانات النسخة القديمة في جميع حالات التثبيت وفشل الجهاز.** وجود نسختين احتياطيتين تم التحقق منهما هو الإجراء الأكثر أماناً.

## طريقة رفع المشروع إلى GitHub Desktop

- نزّل ZIP وفك ضغطه، وانسخ **محتوياته** إلى المجلد المحلي لمستودع `moatezabofakher-hub/sun` مع الحفاظ على مجلدات `.github`, `app`, `tests`، ثم اقبل استبدال الملفات المكررة.
- نفذ `Commit to main` ثم `Push origin`.
- في **Actions** راجع أن المحاولة الجديدة نجحت. نزّل أحدث APK من **Artifacts**، ثم اختبر ماسح الفاتورة وقاعدة البيانات قبل الاعتماد عليه.

لا ترفع مولّد التفعيل الخاص بك أو مفتاحه الخاص أو ملفات النسخة الاحتياطية إلى GitHub.
