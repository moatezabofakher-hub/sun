# إصلاح المزامنة المحلية — الرئيسي 3.5.29 والمندوب 1.2.1

## العطل
ظهرت الرسالة `Error invoking startReceiver` على الرئيسي و`Error invoking send` في تطبيق المندوب.
كان `NativeLocalSync.isTrustedPage()` يستدعي `WebView.getUrl()` مباشرة من خيط JavaScript Bridge الخاص بخلفية WebView، وهذا ممنوع في Android وقد يؤدي إلى Java exception قبل بدء أي اتصال Wi-Fi.

## الإصلاح
- يتم تحديث عنوان الصفحة الرئيسية الموثوقة داخل `MainActivity.WebViewClient.onPageStarted/onPageFinished` على خيط واجهة Android.
- يستخدم `NativeLocalSync` علامة ثقة محفوظة `volatile` بدل استدعاء `WebView.getUrl()` على خيط جسر JavaScript.
- لا يسمح بالاتصال من صفحة غير محلية؛ يبدأ السماح فقط بعد تحميل صفحة أصول التطبيق الموثوقة.
- حافظنا على اتصال Wi-Fi المحلي السابق، والتحقق من هوية الشركة والمندوب والمخزون والتشفير ومنع التكرار.
- لم نغير قاعدة البيانات أو مفاتيح التوقيع أو المعرف البرمجي لأي من التطبيقين.

## التحديث
1. خذ نسخة احتياطية مستقلة من الرئيسي والمندوب.
2. ارفع الملفات المعدلة بمساراتها الصحيحة في GitHub، واحفظ التغييرات على `main`.
3. ابنِ الرئيسي من `Technical Accountant - Signed APK` والمندوب من `Technical Accountant - Agent Signed APK` مع أسرار التوقيع نفسها.
4. تأكد من رقم التطبيق في إعدادات Android: الرئيسي 3.5.29 والمندوب 1.2.1.
5. صل الهاتفين بشبكة Wi-Fi واحدة تسمح بتواصل الأجهزة، افتح شاشة «مندوبو التوزيع» في الرئيسي، واضغط «مزامنة الآن» في المندوب.
6. جرب بفواتير اختبارية وقارن كشف المندوب والمخزون والمقبوضات قبل الاعتماد على بيانات حقيقية.

## حدود التحقق
تم فحص Java syntax عبر نماذج Android، والاختبارات البرمجية للمشروع. لم تتوفر هنا تجربة فعلية على هاتفين، ولذلك لا يمكن ضمان اتصال Wi-Fi قبل الاختبار الميداني. إذا استمرت المشكلة، التقط الرسالة الجديدة أو سجل Logcat الذي يوضح سبب Java exception.

لا تحذف التطبيق ولا تمسح بياناته. إذا كان تطبيق المندوب يملك فواتير غير متزامنة، احتفظ بها واستعمل التبادل بالملفات إلى أن تنجح التجربة.
