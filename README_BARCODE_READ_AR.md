# المحاسب التقني — صوت قراءة الباركود وملف بناء ويندوز

## الجديد
- يصدر صوت عند اكتمال قراءة رمز باركود بواسطة الماسح، وليس بعد إضافة المادة إلى الفاتورة.
- لا يختلف الصوت بحسب نجاح إضافة السطر، وفي ماسح الكاميرا المستمر على أندرويد يصدر عند كل قراءة مقبولة حتى لو لم تُضف بعد للفاتورة.
- قارئ USB/HID يبدأ الإجراء بعد إرسال رمز نهاية القراءة Enter أو Tab. على أندرويد تتطلب القراءة الآلية أن يكون الباركود مرتبطاً بمادة معروفة.
- لن يؤدي الضغط على المادة من الشبكة أو قائمة الأسماء إلى إصدار زمور الباركود.
- عند الحفظ أو إغلاق الماسح المستمر لا يصدر زمور إضافي.

## ويندوز: حل مشكلة اسم ملف ZIP
ارفع ملف Tiqany_Windows_Full_3_5_64.zip إلى جذر مستودع ويندوز (لا ترفعه داخل مجلد).
احذف ملفات ZIP القديمة من جذر المستودع واحتفظ بملف مشروع ويندوز واحد فقط.
افتح .github/workflows/build-windows.yml واستبدل محتواه بمحتوى Tiqany_Windows_Build_Name_Independent.yml، ثم Commit changes.
من Actions اختر Build Tiqany Acc Windows from ZIP ثم Run workflow، وبعد نجاح البناء نزّل Tiqany-Windows-Installer.
ملف البناء يبحث عن ملف ZIP الوحيد في المستودع تلقائياً مهما تغيّر اسمه في الإصدارات اللاحقة، ويتأكد من أنه مشروع ويندوز الصحيح.
يمكن أيضاً فك ضغط المشروع في GitHub واستخدام workflow المرفق داخل المصدر windows-installer.yml؛ لا تخلط طريقتي البناء.

## أندرويد
ارفع كل مشروع إلى مستودعه المناسب، مع المحافظة على مفاتيح التوقيع واسم الحزمة. الرئيسي وموظف البيع داخل مشروع Android Main+Staff، والمستقل مشروع منفصل.
نسخة ويندوز: 3.5.64، أندرويد الرئيسي وموظف البيع: 3.5.65، المستقل: 3.5.62.
قبل تثبيت أي إصدار، خذ نسخة احتياطية كاملة من بيانات التطبيقات. لا تحذف تطبيقاتك الحالية.

## حدود التحقق
نجحت اختبارات المصدر المتاحة؛ لم يُنشأ أو يُختبر ملف EXE أو APK على جهاز فعلي في هذه الجلسة. أجهزة قارئ الباركود المختلفة تحتاج تجربة بعد تثبيت الإصدار الجديد.
