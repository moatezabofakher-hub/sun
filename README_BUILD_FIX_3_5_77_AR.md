# إصلاح فشل إنشاء تطبيق الرئيسي على GitHub — إصدار 3.5.77

**خطأ التطبيق الرئيسي في الإصدار السابق 3.5.76**: فشل ترجمة `MainActivity.java` عندما استُخدم تعبير شرطي مختلط النوع (`String` و`Collection<String>`) كوسيط لدالة `setDesiredBarcodeFormats` في ماسح QR.

## الإصلاح
- استخدام استدعاء منفصل لـ `ScanOptions.QR_CODE` عند ربط الهاتف بالكمبيوتر، واستدعاء منفصل لـ `ScanOptions.ALL_CODE_TYPES` للماسح العام.
- إضافة فحص Java يترجم المقطع الفعلي ضد التواقيع المزدوجة لدالة ZXing، قبل بدء بناء APK على GitHub.
- رفع `versionCode` للتطبيق الرئيسي دون تغيير `applicationId` أو شهادة التوقيع.

## رفع المصدر
1. فك ZIP وأرسل المجلدات إلى نفس مسارات المستودع: `app/` و`field_agent/` و`tests/` و`scripts/` و`.github/workflows/` مع ملفات Gradle في الجذر.
2. **لا ترفع ZIP وحده** إذا كان الإجراء الجاري يفترض وجود `app/build.gradle` في جذر المستودع.
3. افتح Actions > Tiqany Acc - Main Signed Release > Run workflow.
4. ستحصل على APK قابل لتحديث نفس التطبيق فقط إذا كانت أسرار توقيع GitHub هي نفس مفتاح التوقيع القديم.

## التحقق
- نجحت فحوصات المشروع محلياً.
- نجح `javac` في اختبار نوعي جديد لاستدعاء `ScanOptions`، ونجح تحليل بنية ملفات Java الأساسية.
- **لا تتوفر بيئة Android SDK/Gradle للبناء الفعلي هنا**. لا يمكن تأكيد إنتاج APK إلا بعد تشغيل بناء GitHub.
