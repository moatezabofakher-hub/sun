# المحاسب التقني 3.5.95 — تصميم الفواتير والشريط العلوي

أُعد هذا التحديث على أساس مصادر 3.5.94 للكمبيوتر والرئيسي/موظف البيع، ومصدر النسخة المستقلة 3.5.90 المتوفر في المكتبة.

## التغييرات
- يظهر رمز الكمبيوتر والموبايل دون كلمة «متصل». يتغير لون الخلفية والأيقونة بحسب حالة الاتصال التي يوفرها نظام المزامنة الحالي؛ لم تتغير آلية المزامنة.
- عند فتح فاتورة أو سند في الرئيسي أو الكمبيوتر أو المستقل، يُخفى زر الضبط والإشعارات ويظهر زر الرجوع في اليمين يليـه عنوان العملية. تبقى أدوات الشاشة الرئيسية كما كانت.
- يترتب رأس فاتورة البيع/الشراء: الحساب على اليمين والعملة الأصغر على اليسار؛ تحتهما التاريخ والوقت على اليمين والمستودع على اليسار؛ ثم زر طريقة الدفع.
- كل ضغطة على زر طريقة الدفع تحول نقدي ← دفعات ← آجل ← نقدي. تظهر الحالة الحالية بلون مستقل: أخضر/أزرق/أحمر وردي.
- يستخدم التحكم القديم changePaymentMethod نفس المعالجة المحاسبية بعد تغيير الواجهة. دخول وضع دفعات يصفّر المدفوع تلقائياً لتجنب ترحيل إجمالي النقدي كدفعة، ويمكن إدخال الدفعة في الحقل الموجود.
- تعديل موازٍ لواجهة فواتير موظف البيع، بما فيها المستودع المخصص للموظف والواجهة المضغوطة.
- دون حذف البيانات السابقة أو إعادة إنشاء قاعدة البيانات ضمن مصدر التطبيق.

## التحقق
- اختبارات وحدة محلية: Windows 126/126، Android 31/31، مستقل 6/6.
- فحص نحوي لملفات JavaScript المضمنة والخاصة بالموظف.
- لا يشمل الفحص تشغيل APK أو EXE على جهاز حقيقي، أو نجاح مهمة GitHub Actions الفعلية.

## التثبيت
- احتفظ بنسخة احتياطية من بيانات التطبيق قبل تحديث APK أو EXE.
- ارفع *محتويات* مشروع ويندوز بعد فك ضغطه إلى جذر مستودع ويندوز، وليس ملف ZIP إلى مسار src.
- ارفع محتويات مشروع أندرويد الرئيسي/الموظف إلى مستودع بناء أندرويد المخصص، مع ملفات `.github/workflows`.
- نفذ GitHub Actions، واستخدم Artifacts الناتجة لتجربة التطبيق قبل تعميم الإصدار.
