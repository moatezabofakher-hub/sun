# المحاسب التقني — تحديث أندرويد

## ما الذي تغيّر؟

- الاسم الظاهر على هاتف أندرويد: **المحاسب التقني**، مع أيقونة مخصصة قابلة للعرض في الشاشة الرئيسية.
- حل تداخل محتوى WebView مع شريط الإشعارات وأزرار التنقل على أندرويد 15 وما بعده عبر مساحة آمنة (WindowInsets + margins).
- زر الرجوع من الشاشة الرئيسية يعرض **هل تريد الخروج؟**، أما داخل الصفحات فيرجع خطوة واحدة، مع الحفاظ على تأكيد البيانات غير المحفوظة.
- ربط طابعة بلوتوث حرارية مقترنة مباشرة داخل التطبيق باستخدام Android Bluetooth Classic SPP وبيانات ESC/POS (من دون تطبيق RawBT خارجي عند اختيار الوضع المباشر).
- الحفاظ على آلية البصمة الأصلية، قاعدة البيانات المحلية، ترخيص التفعيل بالتوقيع العام، والنسخ الاحتياطي.

## هام جداً قبل تحديث التطبيق الموجود

**هذه النسخة الآمنة تُثبّت بجانب التطبيق القديم، ولا تستبدله ولا تحذف بياناته.** ومع ذلك خذ نسخة احتياطية قبل تجربة الترحيل.

1. افتح التطبيق الحالي على الهاتف.
2. اذهب إلى «الإعدادات والطباعة والنسخ الاحتياطي» ثم اختر «تصدير النسخة الاحتياطية» واحفظ ملف JSON في مكان تستطيع فتحه خارج التطبيق.
3. تحقق من وجود ملف النسخة في «ملفاتي» والتأكد من أنه غير فارغ.
4. حمّل APK الجديد وثبّته **كتطبيق منفصل**، لأن معرف الحزمة هنا `com.sunshine.technicalaccountant` بدلاً من `com.sunshine.accounting`.
5. افتح «المحاسب التقني» الجديد، واستعد ملف JSON القديم من الإعدادات. تأكد من الفواتير والمواد والأرصدة في كلا التطبيقين قبل التفكير في إزالة القديم.
6. التطبيق الجديد له مساحة تخزين وترخيص مستقلان؛ قد يحتاج إلى رمز تفعيل جديد مرتبط بمعرّف الجهاز الجديد. لم يتغير مفتاح التحقق العام ولم يُضمّن المفتاح الخاص في هذا المشروع.
7. النسخ الجديدة من هذا التطبيق ما زالت تصدر بصيغة debug؛ لتحديثها مستقبلاً بسلاسة استخدم مفتاح توقيع ثابت ومحفوظ بأمان خارج المستودع.

## رفع المشروع إلى GitHub

1. ارفع **محتويات** المجلد بعد فك الضغط إلى جذر المستودع في الفرع `main`، **مع الحفاظ على ترتيب المجلدات**. لا ترفع محتويات `app` كملفات مستقلة في الجذر.
2. من github.dev يمكن نقل المجلدات وحفظها عبر Source Control → Stage All Changes → Commit → Push/Sync.
3. في صفحة المستودع تأكد من وجود:

```
.github/workflows/build-apk.yml
app/build.gradle
app/src/main/AndroidManifest.xml
app/src/main/java/com/sunshine/accounting/MainActivity.java
app/src/main/java/com/sunshine/accounting/NativeBluetoothPrinter.java
app/src/main/assets/www/index.html
app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml
tests/test_android_changes.py
```

4. افتح `Actions` واختر `Build SAN SHINE Android APK` ثم `Run workflow` إذا لم يبدأ البناء تلقائياً. بعد نجاح العملية، افتح `Artifacts` لتحميل `ALMOHASEB-ALTEQNI-Android-APK`، ثم فك ضغطه لتثبيت `app-debug.apk` على هاتف أندرويد.

## الطباعة المباشرة مع Xprinter XP-P801A

1. شغّل الطابعة وافتح إعدادات بلوتوث الهاتف، واقترن بها مرة واحدة (يمكن أن تظهر باسم Xprinter أو باسم آخر).
2. افتح «المحاسب التقني» واضغط علامة البلوتوث أعلى الصفحة أو اذهب إلى إعدادات الطابعة.
3. اختر **مباشر داخل التطبيق** أو **تلقائي ذكي**، ثم اضغط **اختيار الطابعة**.
4. اسمح لإذن **الأجهزة المجاورة** عند طلبه؛ اختر الطابعة من قائمة الأجهزة المقترنة.
5. اضغط **طباعة تجريبية سريعة**، ثم جرّب طباعة فاتورة.
6. سيحتفظ التطبيق بالطابعة المختارة لإعادة الاتصال تلقائياً عند الطباعة التالية. يمكن فصلها أو اختيار طابعة مختلفة من نفس القائمة.

**التوافق:** يعتمد الاتصال المباشر على دعم الطابعة لتقنية Bluetooth Classic SPP (Serial Port Profile) وأوامر ESC/POS؛ لا يمكن ضمان الدعم لكل إصدار/طراز دون تجربة على الجهاز. إذا كانت الطابعة تعمل بتقنية BLE فقط فقد يحتاج الاتصال إلى تكييف منفصل. خيار RawBT الخارجي بقي متاحاً عند الحاجة.

## حالة التحقق

تم تنفيذ فحوص المشروع، واختبارات JavaScript والحسابات والتراخيص، والتحقق من بنية Java/XML وأسماء الملفات محلياً. **لم يتم إنشاء APK لهذا التحديث داخل جلسة العمل، ولم يتم اختبار الطباعة عملياً على الجهاز**؛ يجب تشغيل GitHub Actions واختبار الواجهة والطابعة قبل الاعتماد التجاري.
