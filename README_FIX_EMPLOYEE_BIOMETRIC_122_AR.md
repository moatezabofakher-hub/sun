# المحاسب التقني — إصلاح أولوية البصمة في تطبيق موظف البيع (الإصدار الظاهر 122)

## ما تم إصلاحه
- عند تفعيل قفل الموظف من المدير، وإذا كان الموظف قد فعّل البصمة سابقًا بكلمة السر المخصصة له، تُفتح شاشة البصمة تلقائيًا بدل عرض إدخال كلمة السر أولًا.
- حقل كلمة سر الموظف يبقى مخفيًا خلف زر «استخدام كلمة السر بدلًا من البصمة». عند إلغاء البصمة، يبقى زر إعادة المحاولة ظاهرًا ولا تُفرض كلمة السر تلقائيًا.
- في الأجهزة التي لا تعلن قارئها البيومتري ضمن المستوى القوي، يختبر أندرويد مستوى BIOMETRIC_WEAK بعد BIOMETRIC_STRONG. لا يُستخدم رمز قفل الجهاز كبديل في مسار بصمة الموظف؛ البديل الوحيد كلمة السر التي عيّنها المدير.
- عند العودة للتطبيق من الخلفية مع بقاء نافذة القفل، يُعاد طلب البصمة دون ظهور مطالبة قسرية بكلمة السر.
- يحتفظ هاتف الموظف بتفعيل البصمة محليًا عند تعطيل القفل من المدير ثم تفعيله؛ وإذا غيّر المدير كلمة سر الموظف نفسها، يلزم إعادة ربط البصمة بعد التحقق بالكلمة الجديدة.
- لا يملك الموظف وسيلة لإنشاء أو تغيير كلمة سره؛ المدير وحده يضبطها.

## البناء والتحديث
- مشروع أندرويد نفسه يضم المكوّنين app (المدير) وfield_agent (الموظف). لم تُغيّر وظائف المدير أو معرّف أي حزمة.
- يبقى **الإصدار الظاهر 122**؛ رُفع **versionCode لتطبيق الموظف وحده إلى 123** لضمان إمكانية التحديث فوق بناء 122 السابق مع مفتاح التوقيع الأصلي نفسه.
- ارفع محتويات ZIP إلى جذر المستودع ثم شغّل GitHub Actions: «Tiqany Acc - Agent Signed Release». المشروع المرفق **مصدر وليس APK**.
- خذ نسخة احتياطية قبل التحديث، ولا تحذف بيانات الموظف ولا تغيّر مفتاح توقيع APK.

## التحقق
- اختبار محلي لنحو خمس حالات في تدفق فتح البصمة والإلغاء والعودة من الخلفية وتعطيل القفل وتغيير الكلمة، وتدقيق بنية جسر أندرويد؛ لكن لم تُختبر البصمة على هاتف حقيقي، ولم يُبنَ APK محليًا بسبب غياب Android SDK/Gradle.
