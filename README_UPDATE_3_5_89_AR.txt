التقني للمحاسبة — حزمة المصادر المحدثة 3.5.89، مبنية مباشرة على الإصدار 3.5.88
تاريخ التجهيز: 15 تشرين الثاني 2026

المشاريع:
  windows/ : نسخة ويندوز الإدارية (Electron + GitHub Actions)
  android/ : الرئيسي + الموظف (Android)
  solo/    : نسخة أندرويد المستقلة

التغييرات المدمجة:
1) كشف حساب تفصيلي قابل لمشاركة PDF في كل التطبيقات: بيانات الشركة وشعارها، اسم العميل، اختيار فترة البداية والنهاية، الرصيد المدور قبل فترة البداية، حركات الفترة بتاريخها ونوعها ومرجعها وتفاصيلها وسعر الصرف المسجل لكل حركة، الرصيد النهائي لكل عملة مستقلاً، أخضر للزيادة وأحمر للنقصان.
2) حساب مبالغ كشف الحساب ثابت النقطة باستخدام BigInt حتى 8 منازل عشرية. لا تُغيّر بيانات قاعدة الحسابات القديمة، ولا يُحسب سعر الصرف التاريخي بسعر اليوم. تبقى دقة السجلات القديمة حسب ما كان محفوظًا في مصدرها.
3) شبكة 10 صلاحيات للموظف تظهر عند الإنشاء والتعديل في الرئيسي والكمبيوتر، وتُرسل في المزامنة الموثقة: التسعير، العملة، الأرصدة، أسعار الفاتورة، سعر الصرف، الجرد، إضافة الحسابات، إضافة المواد، تعديل العمليات وحذفها.
4) تطبيق الموظف يطبّق الضوابط على الواجهات والإجراءات، ويحفظ سعر الصرف وقت تسجيل العملية؛ يمكنه إضافة مادة جديدة برصيد صفري وإرسالها إلى الإدارة، وحذف عملية محلية غير مُرحّلة عند السماح. العمليات المرحّلة تُصحّح أو تلغى في الرئيسي للحفاظ على سلامة الحسابات.
5) تصدير كشف تاريخي من الموظف متاح عند وجود تاريخ كامل للحساب تم الحصول عليه من الرئيسي؛ إذا كان التاريخ ناقصًا يظهر تحذير ولا يختلق رصيدًا مدورًا.
6) تأمين استلام عمليات إضافة المواد والحسابات وتعديلات المستندات عبر فحص الإذن في جهة الإدارة، وقفل دمج قاعدة بيانات الشركة على نجاح الحفظ وإرجاع التغييرات عند الفشل.
7) إصلاح سير GitHub Actions لإنشاء ويندوز: اكتشاف المصدر من جذر المستودع أو من أرشيف ZIP، اختبار الكود قبل البناء، تعطيل توقيع غير موجود، رفع EXE إلى Artifacts بعد بنائه.

نتائج الفحص في بيئة العمل الحالية:
  Windows: 114 من 114 اختبارًا ناجحًا.
  Android الرئيسي/الموظف: 108 من 108 اختبارًا ناجحًا.
  Android المستقل: 32 من 32 اختبارًا ناجحًا.
  فحص قواعد JavaScript الجديدة: ناجح.
  تحقق خارجي من إتاحة إصدارات Electron 45.3.2 و electron-builder 26.18.0.

ما لم يُختبر بعد:
  - إنشاء EXE على جهاز Windows الحقيقي أو GitHub Actions؛ هذا يتطلب تشغيل Windows runner، لذلك لا يمكن ضمان عدم وجود أخطاء بيئية قبل ذلك.
  - بناء APK واختبار التشغيل والمزامنة على أجهزة أندرويد فعلية؛ Android SDK غير متاح في هذه البيئة.
  - صلاحيات الموظف تحمي الواجهات وبعض أنواع العمليات عند الاستلام؛ لا يمكن اعتبارها حاجزًا ضد تعديل التطبيق الميداني نفسه أو العبث بجهاز جذري الصلاحيات. تحقق الإدارة من التسجيلات المحاسبية قبل اعتمادها يظل مطلوبًا.

رفع نسخة الكمبيوتر إلى GitHub:
  - الخيار الأنظف: فك ضغط ملف نسخة ويندوز، ثم ارفع جميع محتوياته إلى جذر المستودع مع المجلد المخفي .github؛ لا ترفع الملفات إلى مجلد فرعي اسمه windows.
  - أو: ارفع ملف ZIP كاملًا إلى جذر المستودع، وارفع كذلك ملف build-windows.yml المنفصل إلى .github/workflows/build-windows.yml، لأن GitHub لا يقرأ ملفات سير العمل من داخل الأرشيف.
  - من صفحة Actions اختر Build Tiqany Acc Windows EXE ثم Run workflow. عند نجاحه نزّل المثبت من Artifacts.
  - لا ترفع ZIP القديم 88 إلى نفس المستودع مع ZIP الجديد عند اتباع أسلوب ZIP إذا لم يكن هناك داعٍ.

مهم: أنشئ نسخة احتياطية من بياناتك قبل تثبيت التحديث؛ لا تحذف بيانات التطبيق الحالي ولا تغيّر معرف الحزمة عند التحديث.
