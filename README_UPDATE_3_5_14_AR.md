# المحاسب التقني 3.5.14 — الديون والواجهة والتحديث الموقّع

## تعديلات الواجهة

1. عند الضغط على **الديون** في الشاشة الرئيسية تظهر نافذة بخيارين: **لنا** و **علينا**. «لنا» يعرض الحسابات ذات الرصيد المدين لنا، و«علينا» يعرض الحسابات ذات الرصيد الدائن علينا، ويشمل ذلك العملاء والموردين وفق إشارة الرصيد الفعلية، لكل عملة على حدة. حساب برصيد موجب بالليرة وسالب بالدولار قد يظهر في القائمتين لوجود حق والتزام منفصلين.
2. تظهر مجاميع المبالغ «لنا» و«علينا» **في صفحات الديون فقط**، وبالليرة والدولار كل على حدة. صفحة الحسابات العامة بلا مجاميع ديون، وبلا زري سند قبض وسند دفع المكررين؛ يبقى زر إضافة حساب.
3. إصلاح صورتَي قسمَي **اللغة** و**إعدادات الشركة** في الضبط بإضافة SVG محليين إلى ملف `static/icons.js` حتى يعملا دون إنترنت.
4. إخفاء اختصار البلوتوث من شريط عنوان التطبيق العلوي، مع إبقاء إعدادات طابعة البلوتوث داخل **الضبط ← الطباعة**، وتوسيط عنوان المحاسب التقني ووصفه في الصفحة الرئيسية وتكبير أيقونة الضبط.
5. الاحتفاظ بتعديل «×» الأحمر على شبكة الأصناف من الإصدار 3.5.13 وباقي المزايا.

## حماية البيانات والتثبيت

- يبقى **معرّف التطبيق الأصلي** `com.sunshine.technicalaccountant` وقاعدة البيانات `AlRaedAccountingERP_v2` وإصدار القاعدة 1 كما كانت. إصدار APK الجديد `versionCode 21`.
- لن يقبل أندرويد تحديثًا فوق تطبيق مثبّت إذا **اختلف مفتاح توقيعه** حتى مع مطابقة المعرّف ورفع رقم الإصدار. لم يعد مسار البناء يقدّم APK Debug على أنه «تحديث»: عند ضبط أسرار GitHub الأربعة يبني APK إنتاجيًا موقَّعًا، وإلا ينتج نسخة **TEST-DEBUG-NOT-FOR-UPDATING.apk** للاختبار فقط.
- يجب أن يكون **مفتاح التوقيع نفسه** الذي استُخدم في APK المثبّت حاليًا لكي ينجح تحديثه مباشرة ويحتفظ ببياناته. **مفتاح جديد لا يستطيع التوقيع نيابةً عن المفتاح القديم**.
- إذا لم تمتلك المفتاح السابق: صدِّر نسخة احتياطية JSON من التطبيق القديم من **الضبط ← النسخ الاحتياطي**، وتحقق من وجودها ومحتواها على الهاتف وفي مكان آمن خارج التطبيق، **قبل إلغاء تثبيت أي نسخة**. بعد التأكد، ابدأ لأول مرة بنسخة الإنتاج الموقَّعة بالمفتاح الثابت الجديد واستورد النسخة الاحتياطية. قد تحتاج إعادة تفعيل التطبيق؛ الصور والملفات المعاد استيرادها تعتمد على نطاق تغطية تصدير/استيراد النسخة الحالية؛ تحقق يدويًا من عناصرها.
- لا تضع أي ملف `*.jks` أو أسرار أو نسخ احتياطية في مستودع GitHub، وبالأخص المستودع العام. مفتاح التوقيع يجب أن يبقى محفوظًا في مكان خاص ويمكن استرجاعه مدى عمر التطبيق.

## إعداد توقيع ثابت في GitHub Actions (مرة واحدة)

اذهب إلى مستودع GitHub > **Settings > Secrets and variables > Actions > New repository secret** وأضف الأسرار التالية، مستخدمًا ملف الإعداد الخاص السريّ المصاحب **المنفصل عن مشروع المصدر**:

| اسم السر | محتواه |
|---|---|
| `TA_KEYSTORE_BASE64` | نص Base64 الكامل للملف `technical_accountant_release.jks` |
| `TA_STORE_PASSWORD` | كلمة مرور مخزن المفاتيح |
| `TA_KEY_ALIAS` | اسم المفتاح |
| `TA_KEY_PASSWORD` | كلمة مرور المفتاح |

بعد تسجيل الأسرار الأربعة شغّل **Actions > Build SAN SHINE Android APK > Run workflow**. النتيجة: **ALMOHASEB-ALTEQNI-SIGNED-UPDATE.apk** داخل Artifact `ALMOHASEB-ALTEQNI-APK-3-5-14`. احتفظ بأسرار GitHub ومفتاح JKS نفسه لكل التحديثات اللاحقة. لا تستخدم TEST-DEBUG كتحديث.

**تنبيه بالغ الأهمية:** حتى بعد إعداد توقيع ثابت، النسخة التي على هاتفك اليوم قد تكون موقَّعة بمفتاح Debug مختلف؛ لا توجد طريقة برمجية موثوقة لتجاوز تحقق توقيع أندرويد أو نقل بيانات تطبيق ألغيت تثبيته بلا نسخة احتياطية سليمة.
